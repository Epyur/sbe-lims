# AGENTS.md — sbe-lims (ЛИМС)

SBE-плагин «ЛИМС» для сотрудников лабораторий: заявки лаборатории (по `lab_members`),
результаты испытаний по сериям, расчёты (DSL-формулы), классификация, статистика, графики,
протоколы (HTML/docx), справочники лаборатории. Клиент lab-service (сервер — канон).
**Дашборд из плагина удалён (2026-08-18)** — будет вынесен в отдельный плагин; серверный
эндпоинт `GET /api/lab/dashboard` оставлен невостребованным (не удалять).

## Назначение (текущее)

- **Источник данных** — lab-service `https://epyur.fvds.ru` через JWT из ЦУП СБЕ
  (`getService('sbe-apstore').auth.getToken('lab')`, app_id `lab`). Прямые запросы к
  `/api/lab/*` (без локального БД-кэша справочников; заявки/результаты — в памяти вьюхи).
- **Заявки**: список доступных заявок (`GET /requests` — сервер фильтрует по видимости:
  владелец / участник группы / admin / сотрудник лаборатории по `lab_members`), карточка
  с сериями результатов, сменой статуса (`new/received/processing/completed`), графиками
  и протоколом.
- **Результаты**: ввод серии (параметр=значение), сохранение (`POST /results`) —
  сервер автоматически выполняет DSL-формулы/классификацию/статистику; пересчёт серии
  (`POST /results/{series}/calculate`); агрегаты (`GET /results/aggregated`).
- **Справочники**: методы (создание + конфиги formulas/classification/chart_configs/
  input_parameters через JSON-редактор + удаление, всё — admin), испытатели
  (CRUD editor+), оборудование (CRUD editor+), сотрудники лабораторий
  (`lab-members`, admin).
- **Графики**: `GET /requests/{id}/chart/{cfg_id}` → PNG (сервер рендерит по
  `methods.chart_configs`), показываются в карточке заявки.
- **Протокол**: `POST /requests/{id}/protocol` → `{html, docx_base64}`; HTML в модальном
  окне, DOCX скачивается.
- **Точка входа** — магазин: «Установленные → Открыть» (`publishService('sbe-lims', {open})`).
- Вид открывается из ЦУП (`SbeLimsApi extends SbeOpenableApi`), без ribbon.

## Настройки (data.json)

`apiUrl` (default `https://epyur.fvds.ru`). Роли lab (апп-шкала lab_permissions):
`viewer`(1) < `editor`(2) < `admin`(3) < `superadmin`(4, реализована 2026-08-19).
Лабораторный скоуп — `lab_members(lab_id, email, role)`: `lab_operator` / `lab_admin` /
`lab_auditor` (реализована 2026-08-19, см. таблицу ниже).

## Модель прав ЛИМС (переработка согласована 2026-08-18, основное реализовано 2026-08-19)

| Роль | Где | Возможности | Статус |
|---|---|---|---|
| **superadmin** | `lab_permissions` (новая, выше admin) | Создание лабораторий, назначение admin/superadmin. Видит все лаборатории | ✅ реализовано (сервер) |
| **admin** | `lab_permissions` (существующая) | Видит все лаборатории | ✅ (создание лабораторий у admin забрано — теперь только superadmin) |
| **editor / viewer** | `lab_permissions` (существующие, app-level) | Базовые app-level способности | не менялось |
| **lab_admin** | `lab_members` (per-lab) | *Задумано*: управляет своей лабораторией (добавляет участников, правит методы, назначает админов) | ⚠️ **не реализовано** — сервер сейчас не отличает `lab_admin` от `lab_operator` (оба дают только запись результатов через `requireLabAccess`); делегированные полномочия внутри своей лабы без app-level admin — отдельная задача авторизации по ресурсу, не сделана |
| **lab_operator** (испытатель) | `lab_members` (per-lab) | Проводит испытания, вносит данные | ✅ (`requireLabAccess`, как было) |
| **lab_auditor** | `lab_members` (новая, per-lab) | Доступ ко всем разделам своей лаборатории, только чтение | ✅ реализовано (`requireLabRead`: результаты/графики/протокол читает, писать не может) |

Сделано на сервере 2026-08-19 (см. lab-service/AGENTS.md, запись «модель ролей»):
роль `superadmin` (`roleRank`, защита от самоповышения в `handleSetPermission`,
`seedOwner` теперь ставит владельца в superadmin), роль `lab_auditor` + разделение
`requireLabAccess`(запись)/`requireLabRead`(чтение), фильтрация `GET /labs` по
видимости, `POST /labs` → superadmin-only. Плагин: `canAdmin`/`canEditRefs` в
`lims-view.ts` учитывают `superadmin`; `settings-tab.ts` (оба — sbe-lims и sbe-requests)
пускают superadmin к панели прав и добавляют `lab_auditor`/`superadmin` в списки ролей.

⚠️ **Известный пробел, не исправлен**: `POST /requests/{id}/status` проверяет только
видимость заявки (`requestVisible`), не write-право — теоретически статус может
сменить любой, кому заявка видна (например, участник группы), не только
lab_operator/lab_admin/владелец. Не трогали: эндпоинт общий с sbe-requests, а
правильная политика («кто должен мочь менять статус») не зафиксирована ни в одной
спеке — фикс без явного решения рисковал бы регрессией у обоих потребителей.

## Правила

- `catch(e: unknown)` + `errorMessage()`; `requestUrl()` (в `Promise.race` с
  `window.setTimeout`); без `any`; UI на русском; автор — Полищук Евгений (polishchuk@tn.ru).
  Классы `tn-lims-*` / `tn-btn*` / `tn-table` на семантических токенах sbe-core.
- Коммиты/пуши — только по явной команде пользователя.
- **«Фиксируй» = поднять версию (+0.0.1 в `manifest.json` и `package.json`), обновить
  документацию, подготовить сообщение для коммита и СПРОСИТЬ подтверждение commit/push.**
- **Никогда и нигде не использовать «лучше»/«хуже» (и производные: best/worst,
  лучший/худший)** — ни в UI, ни в коде/идентификаторах, ни в комментариях/документации
  (2026-08-22, явное указание пользователя: это оценочные категории, неприменимые к
  объективной оценке результатов испытаний). Только нейтральные сравнительные термины:
  «выше/ниже», «больше/меньше», «максимальное/минимальное». Пример: DSL-функции
  `min_grade`/`max_grade` (не `worst_grade`/`best_grade`), агрегация правил
  классификации `none`/`avg`/`min`/`max` (не `best`/`worst`).

## История работ

### 2026-08-21 — v0.1.14 (конфигуратор методов: атрибуты/формулы/классификация/
представление; ИИ-черновик из стандарта; синонимы для email-импорта)

**Крупная сессия — конфигуратор методов, блоки 1-3 из исходного запроса пользователя.**
Сервер (`server_back/lab-service`) правился в этой же сессии — см. его `AGENTS.md`;
блокирующий баг чтения конфига (там же) обязателен для того, чтобы всё нижеперечисленное
реально видело/сохраняло данные, а не открывалось пустым.

1. **Блок 1 — атрибуты метода** (`input_parameters`, структура вместо raw JSON):
   `renderMethodConfigForm`/`renderAttributeRows` — построчный редактор (id, название,
   тип данных text/int/float/date/time/photo, способ заполнения ручной/прибор/расчёт,
   уровень эксперимент/агрегат). Для расчётных — поле формулы (DSL) + кнопка
   **«🤖 ИИ»** (мини-панель: описание задачи → `LimsLlmAssist.suggestFormula` →
   предложение для правки, никогда не вставляется автоматически). Для агрегированных
   без своей формулы — выбор атрибута-источника + принцип (среднее/минимум/максимум);
   сервер сам строит `formulas[]` из этого (`deriveFormulasFromAttributes`, см.
   lab-service `AGENTS.md`) — клиент formulas не редактирует, только видит (readonly
   `<pre>`).
2. **Блок 2 — правила классификации** (`classification`): построчный редактор трёх
   типов — пороговое (сортировка на сервере, показывается порядок
   `determinable_indicators` метода для наглядности), булево (условие + показатель
   если верно/иначе), **новый тип «соответствие целевому показателю»** (compliance —
   цель всегда `objects.characteristics.target_indicators` заявки, только тексты
   результата редактируются).
3. **Блок 3 — представление данных** (новое поле `presentation`, JSONB-колонка):
   drag-and-drop (нативный HTML5, без библиотек) редактор порядка/подписей/видимости
   столбцов для UI-таблицы результатов и протокола + живой предпросмотр; таблица
   результатов заявки (`renderResultsTable`) и генерация протокола теперь читают этот
   порядок (фолбэк — как раньше, для не сконфигурированных методов). Заодно
   структурный редактор графиков (`chart_configs`, было raw JSON) — карточки
   тип/оси/подписи/ряды, тот же паттерн.
4. **Построчный layout** (по прямому требованию пользователя): одна строка = ВСЕ
   свойства одного атрибута/правила в одном `tn-lims-flex`, не блоки друг под другом.
   Дважды ловил регресс раскладки — сначала `.tn-lims-input`/`.tn-lims-select`
   (`width:100%`) ломали флекс-строку (добавлен override с `flex:1 1 120px` +
   `overflow:hidden` — `<select>` в Electron игнорирует чистый `min-width:0`), потом
   **фикс не применялся вообще**, т.к. правился скомпилированный корневой
   `styles.css`, а не реальный источник `src/styles.css` (`esbuild.config.mjs`
   перегенерирует корневой файл на каждой сборке из `sbe-core` токенов + `src/
   styles.css` — прямые правки корневого файла молча терялись при следующем `npm
   run build`). Раскрываемые панели (ИИ-помощник, синонимы) внутри строки —
   `flex-basis:100%`, чтобы не втискивались в саму строку, а шли под ней.
5. **Импорт конфигурации из стандарта (ИИ-черновик)** — новые
   `services/rtf-to-text.ts` (свой конвертер, RTF-библиотек в проекте нет; cp1251
   `\'XX`-escape через `TextDecoder`, кодовая страница из `\ansicpg` файла, пропуск
   `fonttbl`/`colortbl`/`stylesheet`/`info`/`header`/`footer`/`pict`-групп,
   `\par`/`\row`→`\n`, `\tab`/`\cell`→`\t`; проверено на реальных ГОСТ 30244-94/
   30402-96 — читаемый текст, но числа во встроенных как WMF-картинки таблицах
   не восстановить, ИИ инструктирован не выдумывать такие значения) и
   `services/llm-assist.service.ts` (`draftAttributesAndClassification`,
   `draftPresentation`) — кнопка «📄 Импортировать из стандарта (ИИ)»: файл
   (.rtf/.txt) → черновик атрибутов+правил+представления заполняет те же
   структурные редакторы (никогда не сохраняется автоматически, только после
   «Сохранить»). Санитизация ответа ИИ — транслитерация/дедуп id с картой
   переименований (чтобы formula/aggregation.source не отвязались от своего
   атрибута), отброс нераспознанных `rule_type`/`data_type`. Явная инструкция в
   промпте: id — перевод смысла на английский, НЕ фонетическая транслитерация
   русских слов («flame_duration», не «dlit_plam_gor» — оба варианта разбирались
   на реальном примере с пользователем).
6. **Синонимы атрибута** (`MethodAttribute.synonyms?: string[]`) — кнопка «🔗
   синонимы» на строке атрибута открывает поле альтернативных raw-имён. Решает
   конкретную проблему: ИИ-черновик может назвать параметр иначе, чем уже
   зафиксировано в email-импорте десктопной ЛИМС (`canonicalFieldNames`/
   `knownRawFields`, lab-service) — вместо подгонки имени атрибута под legacy или
   риска расхождения synonyms дают явное маппинг-решение без переименования.
   Обрабатываются на сервере (`resolveResultKey`, приоритет выше глобальных карт) —
   см. lab-service `AGENTS.md`.
7. **Настройка модели LLM** (`SbeLimsSettings.llmModel`, дефолт `gpt-5.6-luna`) —
   `sbe-llm` сам модель не хранит (её выбирает каждый потребитель, как в
   sbe-mailer/sbe-presentations), без неё шлюз chadgpt.ru не гарантирует формат
   ответа, `completeJson` мог падать. Поле в настройках плагина + `LimsLlmAssist.
   resolveModel()`.

   протокола через `keys := map[string]bool{}` — обход `map` в Go недетерминирован,
   порядок столбцов был случайным от рендера к рендеру. Блок 3 (`presentation`)
   чинит это как побочный эффект для ВСЕХ методов (алфавитный фолбэк для
   несконфигурированных), не только сконфигурированных явно.
